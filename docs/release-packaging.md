# Release packaging

The repository uses Bun workspaces for the deterministic corpus library and its
CLI. Run `bun install --frozen-lockfile` with the version pinned in `package.json`
and CI. Shared TypeScript dependency versions live in the root Bun catalog.

## Local verification and builds

```bash
bun run derive
bun run ci
bun run build --out-dir /tmp/plato-site
```

`derive` recreates the 27 ignored token indexes from canonical Greek sources and
the tracked turn indexes. Their regenerated bytes match the former tracked
files. Root `test`, `validate`, `completeness`, and `build` commands rebuild this
cache before consuming it. Other direct CLI commands can use `bun run derive`
first after a fresh clone.

`ci` runs lint, tests, type checking, corpus validation, and a static-site build.
Its default site directory is temporary and is removed after verification.
`build` retains the site in `site/` unless `--out-dir` names another directory.

The public export requires a clean, committed candidate and an external output
directory. From that checkout:

```bash
bun run public:export --out-dir /tmp/plato-public-tree --manifest /tmp/plato-public-manifest.json
bun run release:audit -- --target knowledge-base --public-tree /tmp/plato-public-tree --export-manifest /tmp/plato-public-manifest.json
```

The exporter copies only the tracked public allowlist and records every file's
SHA-256 digest. Ignored token indexes are rebuilt by consumers or supplied as a
separate archive.

## Downloadable candidates

After successful verification, GitHub Actions uploads
`plato-edition-<full-commit-sha>` containing:

- `plato-public-tree.tar.gz`: the audited source and corpus export.
- `plato-site.tar.gz`: the exact built site, including its revision marker.
- `plato-token-indexes.tar.gz`: the reproducible token cache, with paths relative
  to the repository root.
- `public-manifest.json` and `SHA256SUMS`: the inventory and download checksums.

Archives normalize ordering, timestamps, owners, and gzip metadata. The workflow
uses GNU tar on Linux. Download the candidate through the Actions run page or
with `gh run download <run-id> --name plato-edition-<full-commit-sha>`, then verify
it using `sha256sum --check SHA256SUMS` on Linux or
`shasum -a 256 --check SHA256SUMS` on macOS.

These are Actions artifacts with finite retention, not published GitHub
Releases. Promote a verified candidate's existing bytes to a versioned release
when ready. Rendered audio belongs in separate per-dialogue release assets;
keep canonical cast decisions and accepted recording receipts in Git. GitHub
currently allows up to 1,000 assets per release, each smaller than 2 GiB.
See [GitHub's release documentation](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

## Clone cost

Removing the generated token cache reduces the current tracked tree by
70,935,802 bytes (67.65 MiB). Existing Git history still contains those bytes.
A release download avoids Git history; a filtered clone fetches historical file
content only when requested:

```bash
git clone --filter=blob:none https://github.com/mannyc2/plato-wiki.git
```

Full history is needed for the existing snapshot-bound ontology checks. CI
fetches its blobs up front because the audit's individual historical file reads
otherwise cause many separate lazy fetches. The Pages deployment job checks out
only the smoke checker and its library. No history rewrite is part of this
cleanup. Historical ontology audit packages remain in Git because current
validation and accepted provenance still reference them. See the
[Git clone reference](https://git-scm.com/docs/git-clone).

## Build and release libraries

The current product is a static edition plus a checkout-dependent corpus CLI.
Its build runs the existing deterministic site generator. Adding an executable
compiler does not remove the corpus, Python, or audio tool dependencies.
[effect-build](https://github.com/mannyc2/effect-build) currently documents an
unpublished 0.4.0 candidate on Effect v4 RC; defer adoption until a distributable
CLI executable is an actual product requirement.

[ts-release](https://github.com/mannyc2/ts-release) supports archive preparation,
checksums, and resumable GitHub Release publication. Its current documented
execution host is Linux, with Bun 1.3.14 or newer. It is a plausible replacement
for a future Linux publication job after its consumer release is certified;
the local macOS workflow should keep building candidates without it. Neither
library is a dependency of this repository.

The existing two-package layout follows
[Bun workspaces](https://bun.com/docs/pm/workspaces); shared versions use
[Bun catalogs](https://bun.com/docs/pm/catalogs). Additional packages should
represent independently consumed code, rather than subdividing the corpus
directory by file type.
